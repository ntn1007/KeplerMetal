# GPU computation on the Metal buffer linked to its creation reply

On the GTX 880M, two fresh processes each allocate a public 4 MiB shared Metal buffer, match its live wrapper fields to two values from its ordinary creation reply, then run a native Metal compute kernel **on that same buffer**. Each GPU dispatch writes 4,096 32-bit values at byte offset 64. An offline CPU oracle compares all 4,194,304 bytes, including the untouched prefix and suffix. Two matching processes omit the dispatch and preserve the original pattern throughout. All four captures match their respective expected bytes; both GPU results differ from the no-dispatch controls.

This extends the [live resource-reply observation](VIDEO_RESOURCE_REPLY_LIVE.md) to a real GPU operation on the selected NVIDIA `10de:1198` device. It is **not** a video data buffer, video-engine invocation, decoder, driver upgrade or performance benchmark. No video selector or video command is sent. Real video buffer creation, ownership, synchronization, transport and independently verified decoded images remain open.

## Method and limits

The observer forwards the normal selector-0 call generated by Metal unchanged and copies only two 64-bit reply fields into process-local memory after the exact caller, success, lengths and phase match. The host compares these with its live, pinned resource-wrapper fields before creating a compute pipeline. The comparison and intentionally wrong-value check remain inside the process; raw addresses are not exported, so the offline auditor cannot independently recompute this particular correspondence. The full output buffer is captured privately for independent numerical verification.

One inventory, one null-port hook calibration, two no-dispatch controls and two GPU cases run as signed processes with the common cooperative reservation. The profile identifies the selected PCI ancestor and checks the pinned files and loaded-kext/kernel UUIDs; it does not hash live kernel memory or exclude WindowServer. The host writes the initial buffer on CPU, waits for the GPU command to complete and captures the result while the buffer remains alive. The weak Metal wrapper clears after the scoped release, which does not prove kernel resource destruction. The no-dispatch cases build the same public compute pipeline and queue, but submit no GPU command.

The [offline auditor](video-resource-reply-gpu-validation.json) checks signatures, frozen source and support modules, terminal nonoverlapping reservations, profile observations, response and wrapper metadata, command completion, and **16,777,216 captured bytes**. Across the two dispatched processes, **8,192 GPU-written words** match the CPU oracle. [Five offline mutations](video-resource-reply-gpu-mutations.json) alter copied GPU values, boundary bytes, a no-dispatch capture, a response match or terminal state; the auditor rejects them. One earlier exploratory GPU run passed but is excluded from the final cohort. The runner checks support-module hashes before each host; it does not independently attest their execution after an adversarial concurrent change. No system component, OCLP, driver or firmware is modified.

## Reproduction

Use the matching iMac profile, a common cooperative reservation and fresh paths. The inventory supplies the current registry ID. A timeout leaves the exact child unresolved and does not kill it; establish its outcome before another run. Vendor captures and target buffers remain private.

```sh
LAB='/path/to/nvidia-880m-lab/bridge'
E=bridge/experiments/video_resource_reply_gpu
B="$LAB/results/reply-gpu-build-new"
python3 "$E/experiment.py" build --out "$B"
python3 "$E/experiment.py" run --build "$B" --lab "$LAB" --mode inventory --out "$LAB/results/reply-gpu-inventory-new"
RID='<registry_id from inventory verification>'
python3 "$E/experiment.py" run --build "$B" --lab "$LAB" --mode control --registry-id "$RID" --out "$LAB/results/reply-gpu-control-new"
for item in no-gpu:1 gpu:1 gpu:2 no-gpu:2; do
  mode=${item%:*}; n=${item#*:}
  python3 "$E/experiment.py" run --build "$B" --lab "$LAB" --mode "$mode" --registry-id "$RID" --out "$LAB/results/reply-gpu-$mode-$n-new" || exit 1
done
RUNS=("$LAB/results/reply-gpu-inventory-new" "$LAB/results/reply-gpu-control-new" \
 "$LAB/results/reply-gpu-no-gpu-1-new" "$LAB/results/reply-gpu-gpu-1-new" \
 "$LAB/results/reply-gpu-gpu-2-new" "$LAB/results/reply-gpu-no-gpu-2-new")
python3 "$E/audit.py" --build "$B" --prior docs/video-resource-reply-live-validation.json --runs "${RUNS[@]}" --out "$LAB/results/reply-gpu-audit-new.json"
python3 "$E/mutations.py" --build "$B" --prior docs/video-resource-reply-live-validation.json --runs "${RUNS[@]}" --out "$LAB/results/reply-gpu-mutations-new"
```
