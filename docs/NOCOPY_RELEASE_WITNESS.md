# Scoped no-copy release witness

On the tested GTX 880M profile, the native `newBufferWithBytesNoCopy` path did not call the supplied deallocator in the observed window. A process-local, explicitly selected laboratory client now demonstrates a **bounded real release**: after two known Metal commands completed and their outputs matched a CPU oracle, the test's own callback returned its own Mach VM allocation. This is not a system-driver repair, an application-compatible shim, or evidence of general Metal conformance.

The six signed, nonoverlapping hosts include three guarded release cases, one unmodified-path observation, one locally rejected policy and one retained-buffer control. Five hosts dispatch two GPU commands apiece; an independent audit checks 40,960 result words. In the three guarded cases, `mach_vm_deallocate` returned success and a subsequent region query no longer covered the test allocation. Two later callback attempts were generated by the test and rejected as duplicates; they were **not** observed from the native driver. The same two-event guards, extended to wait for the observed root call to return, pass CPU concurrency tests; the three-event test also passes ThreadSanitizer on a separately identified M1 Max.

The experiment checks the current pinned driver and Metal methods, tracks only its selected object, observes the native wrapper's release sequence and waits for both registered GPU commands and output verification. It uses the test's own block and process-owned allocation. No system component is patched. An earlier native callback or mismatched profile is refused by the test guard.

**Limits:** a successful user-space release and a zero native method status do not prove full kernel-object destruction or safety for other queues, clients, workloads, allocations, applications or concurrent native callbacks. The output audit is specific to this cohort. This experiment does not qualify a callback supplied by an ordinary application, live GPU work during release, arbitrary reentrancy, video decoding or performance. Do not deploy it as a replacement driver or use its observed conditions to force-release another allocation.

## Reproduce on the pinned profile

The lab contains the signed hosts and private captures; proprietary Apple/NVIDIA binaries and captures are not distributed. Obtain dependencies as described in [Dependencies](DEPENDENCIES.md). Use fresh paths, the verified current GTX `nvAccelerator` registry ID and the cooperative lab reservation. This experiment uses an actual `mach_vm_deallocate` on its own test allocation.

```sh
LAB='/path/to/nvidia-880m-lab/bridge'
RID='<verified current nvAccelerator registry ID>'
EXP=bridge/experiments/nocopy_gpu_real_release
python3 "$EXP/experiment.py" build --out "$LAB/results/real-release-build-new"
for item in hold-nocopy:1 nocopy-gpu:1 nocopy-repair-gpu:1 nocopy-reject-gpu:1 nocopy-repair-gpu-late:1 nocopy-repair-gpu-late:2; do
  mode=${item%:*}; n=${item#*:}
  python3 "$EXP/experiment.py" run --build "$LAB/results/real-release-build-new" \
    --out "$LAB/results/real-release-$mode-$n" --lab "$LAB" --registry-id "$RID" --mode "$mode" || break
done
python3 "$EXP/audit.py" --build "$LAB/results/real-release-build-new" --runs \
  "$LAB/results/real-release-hold-nocopy-1" "$LAB/results/real-release-nocopy-gpu-1" \
  "$LAB/results/real-release-nocopy-repair-gpu-1" "$LAB/results/real-release-nocopy-reject-gpu-1" \
  "$LAB/results/real-release-nocopy-repair-gpu-late-1" "$LAB/results/real-release-nocopy-repair-gpu-late-2" \
  --out "$LAB/results/real-release-audit-new.json"
xcrun clang++ -std=c++17 -O2 -pthread "$EXP/test_race_gate.cpp" -o "$LAB/results/real-release-race-test-new"
"$LAB/results/real-release-race-test-new"
xcrun clang++ -std=c++17 -O2 -pthread "$EXP/test_once_gate.cpp" -o "$LAB/results/real-release-once-test-new"
"$LAB/results/real-release-once-test-new"
```
